# 练耳扒谱助手 · Guitar Ear Training

[![在线试用](https://img.shields.io/badge/在线试用-guitar--ear--training-2ea44f?style=flat-square)](https://42-beep.github.io/guitar-ear-training/)
[![License: MIT](https://img.shields.io/badge/License-MIT-blue?style=flat-square)](LICENSE)

> 给吉他初学者的练耳扒谱工具：**把别人的指弹谱拆成旋律和伴奏，听一段音频提取出主旋律，再把旋律编配成自己能弹的谱子。**

纯前端、零依赖、单文件。打开 `index.html` 就能用，不联网、不上传、不需要任何 API Key。

**在线使用 → https://42-beep.github.io/guitar-ear-training/**

---

## 为什么做这个

初学者最常见的三个卡点：

1. **想弹一首喜欢的歌，但找不到干净的独奏谱。** 网上流传的指弹谱大多混着伴奏音，看不出哪条线才是旋律。
2. **听不出旋律。** 听着能哼，落到琴上就找不准是哪个音。
3. **会弹单音旋律，但配不出伴奏。** 知道旋律是 `E G A G`，不知道左手该按什么和弦、右手该怎么织体。

这三个卡点对应三个功能页，而且能互相串起来用。

---

## 三个功能

### ① 指弹谱分声部

粘贴 ASCII 六线谱，自动判断每个音是**旋律**（红）还是**伴奏**（蓝），并用 SVG 重新排版。

- 粘贴文本，或直接把 `.txt` / `.tab` 文件拖进来（UTF-8、GBK 编码自动识别，记事本存的也不会乱码）
- 每个音都可以点，判错了点一下就在旋律 / 伴奏之间切换
- 分轨播放：合奏 / 只听旋律 / 只听伴奏
- 速度、每格时值、音色（吉他和钢琴）可调
- 顶部淡红色折线是旋律轮廓，一眼看出走向
- 可导出首调简谱

### ② 音频识旋律

拖入 `mp3 / wav / m4a / ogg`，**整首歌直接丢进来**，或者点「用内置示例试一下」直接体验。

- 默认「歌曲模式」：谐波显著度 + Viterbi 全局路径，直接从混音里挑出最连贯的主旋律线
- 切到「单音模式」：YIN / NSDF 基频检测，清唱、单件乐器时节奏更细
- 音高曲线图（左侧标音名）+ 钢琴卷帘图
- 可试听核对，可导出简谱

### ③ 配指弹谱

**旋律是输入，指弹谱是产物。** 三条路都能进：

```
① 粘贴别人的谱 → 分出旋律 ┐
② 音频识旋律   → 旋律线   ┼→ ③ 编配成指弹谱 → 播放 / 复制 / 送回①微调
③ 手写音名/简谱 → 旋律     ┘
```

输入支持两种写法：

```
音名：E4 G4 A4 G4 C5
简谱：3 5 6 5 1'        （配合 "1 = C"）
时值：E4:2 表示这个音占两格（一格 = 八分音符）
```

可选伴奏密度（稀疏 / 中等 / 密集）、和声密度（每小节 / 每两拍换和弦），生成结果能直接播放或复制成文本谱。

## 原理

### 分声部：允许跳过的动态规划

核心矛盾是"旋律倾向于在高音区"和"旋律线条要平滑"之间的权衡。如果简单地强制**每一列都选一个旋律音**，分解和弦里的过渡音会全被当成旋律 —— 听起来完全不对。

所以状态转移里有第三种选择：**这一列不选旋律音**。因为真实指弹里旋律是延音的，会跨过好几列伴奏音。

代价函数大致是：

```
总代价 = 音高排名代价 + 弦位代价 + |与上一个旋律音的音程| 的代价
```

音程代价是分段线性的 —— 级进（≤5 半音）很便宜，跳进（>12 半音）很贵，中间隔了空拍则放宽。

### 音频：逐帧找基频还是整条路径

一开始用的是逐帧判断：每一帧找"最像基频的那个音"，再做中值滤波。清唱、单件乐器没问题，**但整首歌一旦有人声+伴奏就不行了** —— 贝斯和和弦根音的泛音序列和主旋律长得一模一样，逐帧判断会在两条线之间来回跳。

所以现在默认走"歌曲模式"，两步：

1. **谐波显著度**：给每帧每个候选半音打分，把它的 8 根泛音在对数域加权累加。用对数而不是幅度，是因为"少一根泛音"比"某根泛音特别响"更能说明这不是基频 —— 3 倍频（如 E4 的 B5）这种误判就是靠这条压掉的。
2. **Viterbi 全局路径**：把整首的候选音连成一条总代价最小的路径，音程平滑优先、八度跳进重罚。任何一帧的抖动都会被前后文拉回去。

另外两条先验：

- **上层声部优先**：高音区里有另一个同等强度的音时，压低当前候选（流行歌主旋律基本在最上层）。但要跳过 2/3/4 倍频关系，否则会把某根响的泛音当成更高的声部。
- **谐波齐全度**：低音能凑齐 8 根泛音，高音在 5.5 kHz 以上本来就少，做温和修正。

实测（合成混音，主旋律 16 音）：逐帧法在重度混音下只剩 4/16 命中，Viterbi 版是 16/16；4 分钟音频约 1.3 秒算完。

#### 实测踩过的坑

| 坑 | 现象 | 修正 |
|---|---|---|
| 求自相关时加了汉宁窗 | 置信度被压到 0.38 | 自相关不加窗 |
| 用两次正向 FFT 近似自相关 | 结果放大 N 倍，归一化失效 | 改用共轭求逆变换 |
| 音高转 MIDI 漏除以 440 | 所有音偏高 105 个半音 | `12*log2(f/440)+69` |
| 只按单帧判断音高 | 音符交界处出现八度毛刺 | 帧级 + 音符级双层八度纠正 |
| 静音阈值用绝对值 | 录音底噪被当成音 | 改相对峰值判定 |
| 上层声部先验太猛 | 独奏吉他被追到 3 倍泛音上 | 跳过谐波关系的候选 |
| 谐波用幅度加权平均 | 高把位泛音强的音抢走基频 | 改对数域 + 齐全度修正 |

### 编配：三步都是约束下的最优解

1. **和声**：把旋律按小节切段，用 Viterbi 在全曲上扫出一条最合理的和弦进行。代价 = 旋律契合度（强拍权重更高）+ 和声进行本身的顺畅度（根音上四度最顺）。
2. **低音**：从 E2 往上找和弦根音，第 1、3 拍弹根音，第 3 拍换五音 —— 最常见的交替低音。
3. **旋律定弦**：同一音高有多根弦能弹（A4 = 1弦5品 / 2弦10品 / 3弦14品），用 DP 在"尽量用高音弦"和"左手别来回跳"之间找平衡。

## 使用

### 直接打开

下载仓库，双击 `index.html`。不需要构建、不需要 `npm install`、不需要服务器。

### 部署到 GitHub Pages

```bash
git clone <你的仓库地址>
cd <仓库目录>
```

文件放到仓库根目录后，在 GitHub 仓库页面：

**Settings → Pages → Source 选 `Deploy from a branch` → Branch 选 `main` → 目录选 `/ (root)` → Save**

等一两分钟，访问 `https://<用户名>.github.io/<仓库名>/` 就能在线用，手机也能打开。

因为页面里没有任何外部请求，部署后是完全静态的，不吃流量、不会挂。

## 已知边界

**图片谱（.png / .jpg）不能直接识别。** 六线谱的图像识别对清晰度、拍摄角度、字体要求都很高，纯前端做出来的准确率不可用。目前只支持文本谱 —— 图片需要先手动转成文本，或者用截图工具配合文字识别拿到带横线的文本。

**主旋律不在最上层时会跟错。** 歌曲模式有一条"主旋律通常在最上层"的先验，所以遇到主旋律被高音区铺底（弦乐、合成器）压住的段落，会跟着上面那条线走。这时把「音域范围」调成「中高音」通常能救回来。另外，纯打击乐、说唱这类没有稳定音高的素材本来就没有旋律可抓。

**音频转来的节奏是近似的。** 识别结果只有音高和时值，没有拍号，所以按相对长短折算成格子 —— 比例是对的，但不保证正好落在小节线上。听着不对就去第③页改文本里的 `:2`。

**m4a 不一定是 AAC。** 有些平台（网易云的无损 / 高码率档）下下来的 `.m4a` 里装的是 AVS3（`av3a`）编码，浏览器没有这个解码器。工具会直接报出检测到的编码名，不会只说"解不开" —— 遇到就改下 MP3 音质重下，或转成 mp3 / wav。

**编配只是"合理"，不是"好听"。** 保证旋律音一个不差、和弦在调内、指法能弹，但不会像人一样设计副旋律、加击勾弦、控制声部走向。

**调性判断在关系大小调之间会有歧义。** 比如 C 大调和 A 小调共用同一批音。所以"1 = ?"下拉框始终可以手动指定，不让你被自动结果绑住。

## 技术

- 单文件 HTML + 原生 JS，无框架、无构建、无依赖
- 谱面用 SVG 手绘，图表用 Canvas 2D
- 音频用 Web Audio API 做解码、降采样、合成音色（Karplus-Strong 物理建模）
- 所有计算在浏览器本地完成
